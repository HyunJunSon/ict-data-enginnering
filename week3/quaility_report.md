# 3주차 산출물 — 데이터 품질 리포트

## 1. 대상
- 원본: orders.csv (1,015행) — 3-1에서 생성, 시드 고정
- 정제 결과: orders_clean.parquet (1,000행)
- 파이프라인: clean_orders.py (DuckDB 추출 + Pandas 정제)

## 2. 품질 지표 전후 비교
| 지표 | before | after |
|---|---|---|
| 행 수 | 1,015 | 1,000 |
| order_id 중복 | 15 | 0 |
| price 결측 | 30 (2.96%) | 0 |
| category 고유값 | 5 | 4 |

## 3. 처리 내용과 근거
| 문제 | 처리 | 근거 |
|---|---|---|
| category 앞뒤 공백 20건 | str.strip() | ' 식품 '이 '식품'과 다른 값으로 잡혀서 카테고리가 5개로 세어졌다 |
| order_date 타입 | to_datetime() | DuckDB로 읽으면 이미 날짜지만 pd.read_csv로 읽으면 문자열이라, 입력 경로가 달라도 같은 결과가 나오도록 변환을 남겼다 |
| order_id 중복 15건 | drop_duplicates(keep='first') | 같은 주문이 두 번 집계되면 매출이 그만큼 부풀려진다 |
| price 결측 30건 | 중복 제거 뒤 중앙값으로 보정 | 결측률 2.96%로 낮고, 중앙값은 이상치에 덜 흔들린다. 보정을 중복 제거보다 먼저 하면 중앙값 자체가 달라진다(100,500 vs 101,000) |

## 4. 고치지 않은 것
- amount는 price * quantity로 새로 만들었지만, quantity가 0이거나 음수인 행을 따로 거르지는 않았다. 지금 데이터에는 그런 값이 없어 넘어갔다.

## 5. 검증
- 재실행 검증: 같은 원본으로 두 번 돌려 결과가 같은지 확인 (equals() True)
- 교차 검증: DuckDB로 다시 세어 Pandas 결과와 맞는지 확인
- 유효성 검사: 음수 가격·수량, 미지 카테고리 0건
- 검사기 자체 검증: 일부러 나쁜 값을 넣어 검사기가 걸러내는지 확인

## 6. 남은 과제
- 중앙값 보정은 결측을 메우긴 하지만 분포를 한 점으로 몰아 price의 분산을 줄인다. 결측이 더 늘어나면 보정 방식을 다시 봐야 한다.
- 검증 항목(음수·미지 카테고리 등)이 리포트 설명으로만 있고 clean_orders.py 안에 들어가 있지 않다. 자동으로 돌도록 코드에 옮기면 다음 데이터에서도 바로 걸러낼 수 있다.
- order_id가 중복될 때 무조건 첫 행을 남기는데, 어느 행이 맞는 기록인지 판단하는 기준은 아직 없다.
